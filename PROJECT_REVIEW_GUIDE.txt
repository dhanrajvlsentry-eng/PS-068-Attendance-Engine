1. HOW TO RUN
================================================================================

1.1 Prerequisites
-----------------
- Python 3.10+ (tested and verified on Python 3.12).
- Standard packages installed via requirements.txt:
  pandas, numpy, python-dateutil, pytest, pytest-cov, tabulate.

1.2 Virtual Environment Activation
----------------------------------
- Windows PowerShell:
    .\.venv\Scripts\Activate.ps1
- Windows CMD:
    .\.venv\Scripts\activate.bat
- Linux / macOS:
    source .venv/bin/activate

Install dependencies (if setting up fresh):
    pip install -r requirements.txt

1.3 Exact Commands to Run the Project
-------------------------------------
1. Primary Command-File Driven Workflow:
    python main.py
   (Executes the complete end-to-end pipeline using ./command.txt)

2. Run with a Custom Command File:
    python main.py --commands data_v2/commands.txt

3. Run the Evaluation Data Engine (Generates evaluation CSVs):
    python engine_v2.py

4. Run the Full Automated Test Suite (117 test cases):
    python -m pytest tests/ -v

1.4 Role of main.py
-------------------
`main.py` is the application entry point and central orchestrator:
- Parses CLI arguments (`--commands`, `--data-dir`, `--generate-data`, `--verbose`).
- Maintains the mutable application state (`AppState`: students, courses,
  calendar, timetable, attendance records, OD approvals, condonations, audit log).
- Registers command handlers with `CommandParser`.
- Reads and executes commands from `command.txt` sequentially in file order.
- Rebuilds managers and calculation caches on demand when data changes.
- Coordinates reporting and user output.

2. HOW THE PROJECT WORKS
================================================================================

2.1 How CSV Datasets Are Loaded
-------------------------------
The module `src/data_loader.py` reads academic CSV datasets with dual-schema
compatibility (supporting both initial v1 and new sample dataset v2 formats):
- `students.csv`: Maps `register_no` / `student_id`, name, section, admission date,
  lateral entry flag, parent mobile. Enriches programme/semester from `sections.csv`.
- `courses.csv`: Course code/ID, course name, section, weekly periods, lab flag, faculty ID.
- `calendar.csv` / `academic_calendar.csv`: Day types (WORKING, HOLIDAY, WORKING_SATURDAY),
  and timetable mappings for working Saturdays.
- `timetable.csv`: Period slots (1-6) per section and weekday with assigned courses.
- `attendance.csv`: Period-level attendance marks for conducted classes.
- `placement_drives.csv`: Drive dates, company names, eligible programmes.
- `applications.csv`: Condonation requests with date ranges, leave type, certificate refs.

2.2 How command.txt Controls Execution
--------------------------------------
PS-068 is strictly command-file driven. `src/command_parser.py` reads `command.txt`
line by line, ignores blanks and `#` comments, and executes commands strictly in order:
- `LOAD_DATA data_v2`
- `CALENDAR_SUMMARY`
- Dynamic registrations: `REGISTER_STUDENT`, `REGISTER_COURSE`
- Approvals: `APPROVE_OD`, `APPLY_CONDONATION`, `APPROVE_CONDONATION`
- Warning letter runs: `GENERATE_WARNING_LETTERS <date> <run_no> <dir>`
- Post-freeze principal correction: `PRINCIPAL_CORRECTION`
- Report generation: `GENERATE_ATTENDANCE_REPORT`, `GENERATE_COURSE_WISE_REPORT`,
  `GENERATE_OVERALL_REPORT`, `GENERATE_ELIGIBILITY_REPORT`, `GENERATE_SHORTAGE_REPORT`,
  `GENERATE_FEE_REPORT`, `GENERATE_FINE_REPORT`, `GENERATE_PARENT_MEETING_REPORT`, etc.
- Console summaries: `SHOW_SECTION_ATTENDANCE`, `SHOW_CONDONATION_SECTION`

2.3 How Attendance Is Calculated (src/attendance_calculator.py)
--------------------------------------------------------------
For each student and course:
1. Conducted Period Check: Only periods where faculty submitted attendance are counted.
2. Holiday Rule: Records logged on declared holidays are ignored.
3. Working Saturday: Follows the timetable of the replaced weekday.
4. Lab Weighting: Lab courses count as 2 periods per conducted session.
5. LATE Grace Window: `arrival_minute <= 10` is counted as PRESENT; > 10 is ABSENT.
6. OD Verification: Attendance marked as OD counts as PRESENT only when matched with
   an approved OD record in `od_approvals` (or verified placement calendar).
7. Lateral Entry: Admitted <= 30 days into semester calculates attendance from admission;
   admitted > 30 days is counted from semester start.

2.4 How Condonation & Eligibility Are Decided (src/condonation_engine.py)
------------------------------------------------------------------------
Processed in strict regulatory order:
1. Medical Leave:
   - Approved medical periods are removed from BOTH conducted and attended counts.
   - Cap: maximum 15% of conducted periods per course (fractional caps truncated/handled).
   - Requires certificate ref; must be submitted within 7 days of return date.
2. Duty Days (Sports / NCC / NSS):
   - Approved duty days are added to attended count.
   - Cap: max 20 duty days per semester overall, max 10% of post-medical conducted periods.
3. Placement Leave:
   - Final-year students only, matching confirmed dates in placement_calendar. No percentage cap.
4. Bereavement Leave:
   - Max 5 consecutive calendar days, once per semester, submitted within 3 days.
5. Final Course Eligibility:
   - >= 75.00%: ELIGIBLE
   - 65.00% to 74.99%: CONDONABLE
   - < 65.00%: DETAINED
6. Semester Status Rule:
   - Maximum 2 courses can be condoned per semester.
   - A 3rd condonable course automatically becomes DETAINED.
   - 3 or more detained courses cause whole-semester DETAINED status.
7. Condonation Fees:
   - 70.00% - 74.99%: Rs 500 per condoned course.
   - 65.00% - 69.99%: Rs 1,000 per condoned course.
   - Max 2 courses condoned (max fee: Rs 2,000).
8. Absence Fines:
   - Unbroken stretch of 3 or more consecutive full days absent without approved leave.
   - Rs 100/day starting from day 3. Semester cap: Rs 2,000.

2.5 OD Approvals, Corrections & Warning Letters
-----------------------------------------------
- Freeze Date Rule: Attendance freezes 7 days before exam start (2026-11-23).
  Applications submitted post-freeze are rejected as REJECTED_FROZEN.
- Post-Freeze Corrections: Ordinary corrections fail; only `PRINCIPAL_CORRECTION`
  is permitted, and every change is recorded in `AttendanceCorrectionLog`.
- Warning Letters (WarningManager):
  - Run 1 (Month 1): Below 80% receives FIRST_WARNING.
  - Run 2 (Month 2): Below 75% receives SECOND_WARNING (with parent copy).
  - Run 3 (Month 3): 3 consecutive monthly runs < 75% triggers PARENT_MEETING flag.
  - Deduplication: Each warning level is issued at most once per student.

2.6 How Reports Are Generated (src/report_generator.py)
-------------------------------------------------------
- Multi-criteria filtering by student ID, section, course ID, date cut-off, semester.
- Automatic section detection: detects sections present in registered student data
  (`SEC-CS5A`, `SEC-IS5A`, `SEC-EC3A`, `SEC-ME7A`), generates reports for matching
  sections, and cleanly skips missing sections without errors or empty stubs.

5. REVIEWER QUESTIONS & ANSWERS
================================================================================

Q1: Why is this system driven by a command file instead of a GUI or web interface?
A1: The PS-068 problem specification requires an automated, batch-oriented, auditable backend
    engine that can process institutional datasets deterministically and integrate directly
    into automated academic evaluation pipelines.

Q2: How does the engine distinguish between unconducted classes and student absences?
A2: A period is only considered "conducted" if an attendance record exists with a valid faculty ID.
    If faculty did not take attendance or if the day was a holiday, the period is not counted
    in conducted periods.

Q3: How are Lab sessions weighted compared to Theory classes?
A3: Lab courses are flagged with `lab=True` and have a period weight of 2. Each conducted lab
    block counts as 2 periods in both conducted and attended totals.

Q4: How is a LATE attendance record handled?
A4: An arrival grace window of 10 minutes is enforced. If `arrival_minute <= 10`, it counts
    as PRESENT. If `arrival_minute > 10` or unrecorded, it counts as ABSENT.

Q5: In what exact order are condonation applications processed?
A5: First, approved medical leave periods are subtracted from both conducted and attended totals
    (capped at 15%). Next, post-medical conducted counts are calculated. Then approved duty days
    (Sports/NCC/NSS/Placement) are added to attended counts (subject to semester and course caps).
    Finally, percentages, eligibility status, condonation fees, and absence fines are calculated.

Q6: What happens if a student has 3 courses between 65% and 74.99%?
A6: University regulations allow at most 2 courses to be condoned per semester. The third
    condonable course is automatically downgraded to DETAINED.

Q7: What is the rule for Whole-Semester Detention?
A7: If a student accumulates 3 or more DETAINED courses (either through < 65% attendance or
    excess condonable courses), their overall semester status becomes DETAINED.

Q8: How does the freeze date policy protect attendance integrity?
A8: Attendance freezes 7 days prior to exam start. Condonation applications submitted after
    freeze date are rejected as REJECTED_FROZEN. Regular faculty corrections are blocked;
    only PRINCIPAL_CORRECTION is accepted and logged with an audit trail.

Q9: How are absence fines calculated?
A9: Fines apply to unbroken streaks of 3 or more full consecutive working days of unapproved
    absence. The fine is Rs 100/day starting on the 3rd day, up to a semester cap of Rs 2,000.
    Approved leave breaks the streak.

Q10: How does the warning letter deduplication mechanism work?
A10: WarningManager tracks letters issued across monthly runs. Each warning level
     (FIRST_WARNING, SECOND_WARNING) is issued at most once per student per semester.
     A student below 75% for 3 consecutive monthly evaluations receives a PARENT_MEETING flag.

Q11: How does the engine handle lateral entry students?
A11: If a lateral-entry student is admitted within 30 days of semester start, attendance is
     calculated from their admission date. If admitted after day 30, attendance is calculated
     from semester start, treating earlier days as absent.

Q12: How are percentages rounded?
A12: Percentages are calculated using standard Decimal round-half-up rounded to two decimal
     places (e.g. 74.995% rounds to 75.00%, while 74.994% rounds to 74.99%).

Q13: How does the engine handle datasets that contain only Section A without Section B?
A13: The report generator dynamically queries registered students for available sections.
     Section A commands execute and generate populated reports, while missing sections
     (like Section B) are automatically and silently skipped without generating errors or empty files.

Q14: How is system performance ensured across large datasets (e.g., 40,000 records)?
A14: Records are indexed in memory using dictionary hash maps keyed by (student_id, course_id)
     and dates. Lookup operations are O(1), allowing 14,000+ records to be processed in < 1 second.
